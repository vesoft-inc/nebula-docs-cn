# 使用 BR（企业版）备份数据

用户可以备份 Nebula Graph 企业版数据。支持增量和全量备份，支持备份数据至本地及兼容亚马逊对象存储（Amazon S3）服务接口的云服务中。本文介绍如何备份数据。

## 背景信息

- 全量备份是指将数据库中的所有数据备份到一个文件中。
- 增量备份是指备份上一次备份后变化或者修改过的数据。上一次备份可以是全量备份或者增量备份。在对某个目标进行增量备份前，对该目标必须进行过一次全量备份。

## 准备工作

- 确认 Nebula Graph 服务正在运行中。

- 已安装 [BR 企业版工具和 Agent 插件](2.install-tools.md)并在集群中的每个机器上运行 Agent。

- 如果在本地保存备份文件，需要在 Meta 服务器、Storage 服务器和 BR 机器上创建绝对路径相同的目录，并记录绝对路径，同时需要保证账号对该目录有写权限。

  !!! Note

        在生产环境中，我们建议用户将 NFS (Network File System）存储设备挂载到 Meta 服务器、Storage 服务器和 BR 机器上进行本地备份，或者使用 Alibaba Cloud OSS、Amazon S3 进行远程备份。否则当需要通过本地文件恢复数据时，必须手动将这些备份文件移动到指定目录，会导致数据冗余和某些问题。更多信息，请参见[使用 BR 恢复数据](4.br-restore-data.md)。

## 备份数据至云服务

!!! note

    只支持备份数据至兼容亚马逊 S3 协议的云服务中。

### 全量备份数据至云服务

在 BR 企业版工具安装目录下执行以下命令备份整个集群数据至云服务：

```
./br backup full --meta <ip_address:port> --s3.access_key <access_key> --s3.secret_key <secret_key>  --s3.region <region_name> --storage s3://<storage_path> --s3.endpoint <endpoint_url>
```

例如，对 Meta 服务的地址为`192.168.8.129:9559`的整个集群进行全量备份操作，并将备份文件保存至 Amazon S3 服务`nebula-br-test`存储桶的`/`路径下。

```
./br backup full --meta 192.168.8.129:9559 --s3.access_key QImbbGDjfQExxx --s3.secret_key dVSJZfl7tnoFq7Z5zt6sfxxxx  --s3.region us-east-1 --storage s3://nebula-br-test/ --s3.endpoint http://192.168.8.xxx:9000/
```

### 增量备份数据至云服务

在 BR 企业版工具安装目录下执行以下命令备份增量数据至云服务：

```
./br backup incr --meta <ip_address:port> --s3.access_key <access_key> --s3.secret_key <secret_key>  --s3.region <region_name> --storage s3://<storage_path> --s3.endpoint <endpoint_url> --base <backup_file_name>
```

例如，对 Meta 服务的地址为`192.168.8.129:9559`的整个集群基于备份文件`BACKUP_2022_08_11_09_11_07`进行增量备份操作，并将备份文件保存至 Amazon S3 服务`nebula-br-test`存储桶的`/`路径下。

```
./br backup incr --meta 192.168.8.129:9559 --s3.access_key QImbbGDjfQExxx --s3.secret_key dVSJZfl7tnoFq7Z5zt6sfxxxx  --s3.region us-east-1 --storage s3://nebula-br-test/ --s3.endpoint http://192.168.8.xxx:9000/ --base BACKUP_2022_08_11_09_11_07
```

### 参数说明
| 参数 | 数据类型 | 是否必需 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `-h`,`--help` | - | 否 | 无 | 查看帮助。 |
| `--debug` | - | 否 | 无 | 查看更多日志信息。 |
| `--log` | string | 否 | `"br.log"` | 日志路径。 |
| `--meta` | string | 是| 无 | 集群中任一 Meta 服务的地址和端口号。 |
| `--storage` | string | 是 | 无 | 备份数据存储位置，格式为：`storage s3://<storage_path>`。<br>`<storage_path>`：存储位置的路径。|
| `--s3.access_key` | string | 否 | 无 | 用于标识用户。 |
| `--s3.endpoint` | string | 否 | 无 | S3 对外服务的访问域名的 URL，指定 http 或 https。 |
| `--s3.region` | string | 否 | 无 | 数据中心所在物理位置。 |
| `--s3.secret_key`| string | 否 | 无 | 用户用于加密签名字符串和用来验证签名字符串的密钥，必须保密。 |

## 备份数据至本地

!!! caution

    备份至本地时，默认只备份 leader metad 和 leader storaged 的数据，因此当有多个 metad 和 storaged 时，需要手动将备份后的 leader metad 的目录（路径为`<storage_path>/meta`）拷贝并覆盖其他 follower metad 节点的对应目录，并将 leader storaged 的目录中对应的分片数据（路径为`<storage_path>/<part_id>）拷贝至其他 follower storaged 对应的目录中。

### 全量备份数据至本地

在 BR 企业版工具安装目录下执行以下命令备份整个集群数据至本地：

!!! note

    确保备份文件的路径存在。

```
./br backup full --meta <ip_address:port> --storage local://<storage_path>
```
- `<ip_address:port>`：填写集群中任一 Meta 服务所在机器的 IP 地址和端口号。
- `<storage_path>`：填写备份文件的存储路径。

  
例如：对 Meta 服务的地址为`192.168.8.129:9559`的整个集群进行全量备份操作，并将备份文件保存到本地的`/backup/`路径下。

```
./br backup full --meta "192.168.8.129:9559" --storage "local:///backup/"
```

### 增量备份数据至本地

在 BR 企业版工具安装目录下执行以下命令备份增量数据至本地：

!!! note

    确保备份文件的路径存在。

```
./br backup incr --meta <ip_address:port> --storage local://<storage_path> --base <backup_file_name>
```

- `<ip_address:port>`：填写集群中任一 Meta 服务所在机器的 IP 地址和端口号。
- `<storage_path>`：填写备份文件的存储路径。
- `<backup_file_name>`：上一次备份的文件名。基于此备份文件，进行增量备份。


例如：对 Meta 服务的地址为`192.168.8.129:9559`的整个集群基于备份文件`BACKUP_2022_08_11_09_11_07`进行增量备份操作，并将备份文件保存到本地的`/backup/`路径下。

```
./br backup incr --meta "192.168.8.129:9559" --storage "local:///backup/" --base BACKUP_2022_08_11_09_11_07
```

## 下一步

备份文件生成后，可以将备份文件的数据恢复到 NebulaGraph 中。具体操作，参见[恢复数据](4.restore-data.md)。

!!! caution

    请勿修改备份文件的名称及路径，否则会导致恢复数据失败。
