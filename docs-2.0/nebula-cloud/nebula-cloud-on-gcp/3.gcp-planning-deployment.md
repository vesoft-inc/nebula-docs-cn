# 部署准备

开始部署 NebulaGraph Cloud GCP 版的服务集群前，用户需要具备谷歌云平台和 NebulaGraph 的相关知识，准备好 GCP 账号以及相关资源。

## 知识准备

用户需要熟悉谷歌云的常用服务，尤其是 Compute Engine 和 VPC。谷歌云新用户可以通过 [Google Cloud essentials](https://cloud.google.com/docs/get-started#google-cloud-essentials) 学习相应的知识。

## 账号与权限

如果还没有谷歌云账号，先[创建一个账号](https://console.cloud.google.com/freetrial?_ga=2.189064299.1320456914.1661838962-704336122.1649316074&_gac=1.261769087.1661841350.CjwKCAjwx7GYBhB7EiwA0d8oe1BnSsVFHk3AFov1HWrFGX4ZqXZfHXVLk3LwdY_yyxWWYElEA5m8yxoCN8EQAvD_BwE)。

部署用的账号必须有访问项目和使用相关资源的[权限]((https://cloud.google.com/deployment-manager/docs/access-control))。

## 项目与结算

部署前必须准备好一个谷歌云项目。如果还没有，或者想要使用新项目，先[创建项目](https://cloud.google.com/resource-manager/docs/creating-managing-projects)。

要使用 Deployment Manager 在一个项目中部署 NebulaGraph，用户需要先为该项目[启用结算功能](https://support.google.com/cloud/answer/6293499#enable-billing)。查看结算功能是否已启用的方式参见[验证项目的结算状态](https://cloud.google.com/billing/docs/how-to/verify-billing-enabled)。

## 资源额度

开始部署前，在控制台的 [Quotas 页面](https://console.cloud.google.com/iam-admin/quotas)和文档的 [Deployment Manager 限制与额度页面](https://cloud.google.com/deployment-manager/quotas)了解资源额度信息，确认有充足的资源完成部署。部署一套[典型的 NebulaGraph 架构](2.gcp-architecture.md)需要的主要资源如下：

| 资源 | 部署需求数 |
| - | - |
| VPC 网络 | 1 个 |
| 防火墙规则 | 5 条 |
| 虚拟机实例（NebulaGraph Dashboard 主机） | 1 个 |
| 虚拟机实例（NebulaGraph Explorer 主机） | 1 个 |
| 虚拟机实例（graphd 主机） | 3 个 |
| 虚拟机实例（metad 主机） | 3 个  |
| 虚拟机实例（storaged 主机） | 3 个 |

用户可以根据需要自定义部署架构。部署需要的虚拟机实例数取决于实际部署架构。关于 graphd、metad、storaged 主机的数量：

- Graph 服务应用无状态设计，可以有多个 graphd 主机。
- Storage 服务依赖于 Raft 协议，而 Raft 协议是基于多数派投票机制的，因此 storaged 主机的数量必须是奇数。
- Meta 服务同样依赖于 Raft 协议。建议在生产环境中使用三台 graphd 主机。

如果所需的资源不足，先申请增加额度。

## GCP 地区与可用区

如果需要用特定类型的虚拟机实例部署，先查看[可用区域和地区](https://cloud.google.com/compute/docs/regions-zones)确保在要部署的区域和地区中能够使用需要的实例类型。
